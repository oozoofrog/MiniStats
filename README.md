# MiniStats

**Mac의 CPU·메모리 사용량을 메뉴바에서 확인하고, 오래된 Xcode 캐시를 골라 정리하세요.**

MiniStats는 Apple Silicon용 네이티브 macOS 메뉴바 앱입니다. 메뉴바의 작은 수치를 클릭하면 실시간 그래프, 리소스를 많이 사용하는 프로세스, 네트워크와 스토리지 상태를 한눈에 볼 수 있습니다. AppKit과 SwiftUI로 만들었으며 외부 패키지 없이 빌드합니다.

## 주요 기능

| 기능 | 제공 정보 |
| --- | --- |
| 메뉴바 모니터 | 위쪽 CPU, 아래쪽 메모리 사용률. 스토리지 사용률 50% 이상이면 경고 아이콘 표시 |
| 실시간 대시보드 | CPU·메모리 사용률과 최근 추이, 각 상위 프로세스 3개 |
| 프로세스 상세 | CPU·메모리 기준 상위 5개, 프로세스 이름·PID·사용량, 메모리 압력과 스왑 |
| 네트워크·스토리지 | 다운로드·업로드 속도, 디스크 사용률·여유 공간·Finder 기준 사용 가능 공간 |
| DerivedData 정리 | 8시간 이상 사용하지 않은 Xcode 캐시 조회, 항목별 선택과 용량 합계, 삭제 전 확인 |
| macOS 연동 | 로그인 시 자동 실행, 스토리지 알림, 배터리 상태, 활성 상태 보기·Finder 바로가기 |

macOS 26 이상에서는 네이티브 유리 효과를, macOS 13~25에서는 시스템 반투명 소재를 사용합니다. 화면은 시스템의 밝은·어두운 모드와 투명도 줄이기·동작 줄이기 설정을 따릅니다.

## 시작하기

### 요구 사항

- **실행:** Apple Silicon Mac, macOS 13 이상, `/usr/bin/python3`.
- **빌드:** macOS 26 SDK 이상을 포함한 Xcode 또는 Command Line Tools. 빌드 대상의 최소 OS 버전은 macOS 13입니다.
- Python 정리 도구는 표준 라이브러리만 사용합니다. 별도 패키지 설치는 필요하지 않습니다.

### 소스에서 빌드

```sh
git clone https://github.com/oozoofrog/MiniStats.git
cd MiniStats
make verify
open build/MiniStats.app
```

`make verify`는 빌드 환경 확인, 릴리스 빌드, Swift·Python 검사, 번들·서명·아키텍처 검증을 실행합니다. 결과 앱은 `build/MiniStats.app`, 전체 로그는 `build/logs/`에 생성됩니다. 로컬 빌드는 ad-hoc 서명을 사용합니다.

### 설치와 업데이트

계속 사용할 앱은 Finder에서 `build/MiniStats.app`을 원하는 Applications 폴더로 복사한 뒤 실행하세요. 업데이트할 때는 실행 중인 MiniStats를 설정에서 종료하고 새 빌드로 교체합니다. 빌드 명령 자체는 설치본을 덮어쓰지 않습니다.

첫 실행에는 **알림 권한을 요청하고 로그인 자동 실행을 등록**합니다. 자동 실행은 앱의 설정에서 해제할 수 있습니다. macOS가 승인을 요구하면 같은 설정 화면에서 시스템 설정을 열 수 있습니다.

## 사용법

1. 메뉴바의 CPU·메모리 수치를 클릭해 대시보드를 엽니다.
2. CPU 또는 메모리 카드를 누르면 상위 프로세스 상세 화면으로 이동합니다. 탭을 전환해 정렬 기준을 바꿀 수 있습니다.
3. 스토리지 카드를 누르면 여유 공간과 DerivedData 정리 후보를 확인할 수 있습니다.
4. 오른쪽 위 설정에서 자동 실행, 알림 설정, 앱 종료를 관리합니다.

CPU·메모리·네트워크는 **3초마다** 갱신합니다. 그래프에는 최근 40회, 약 2분의 측정값을 표시하며 앱을 종료하면 기록을 유지하지 않습니다. 프로세스 목록은 대시보드가 열려 있을 때만 조회합니다. 메모리 순위는 첫 조회부터, CPU 순위는 두 번째 조회부터 표시됩니다.

### DerivedData 정리

DerivedData는 Xcode가 빌드 결과와 중간 파일을 저장하는 캐시입니다. MiniStats는 앱 시작 시와 이후 1시간마다 용량을 조회합니다. 스토리지 화면의 새로고침 버튼으로 다시 조회할 수도 있습니다.

1. Xcode와 `xcodebuild`를 종료합니다.
2. 스토리지 화면에서 정리할 후보를 선택합니다. 공용 캐시는 기본적으로 보존하며, 필요할 때 포함할 수 있습니다.
3. 선택한 개수와 용량을 확인하고 정리 버튼을 누릅니다.
4. 확인 창에서 대상 항목을 검토한 뒤 **정리 실행**을 누르면 영구 삭제됩니다. 정리 중에는 새 빌드를 시작하지 마세요.

삭제 대상은 **8시간 이상 사용하지 않은 후보 중 직접 선택한 항목**으로 한정됩니다. 자동 삭제는 하지 않습니다. 선택한 항목이 사라졌거나 최근 사용되어 더 이상 후보가 아니면 삭제를 시작하기 전에 중단합니다. 삭제 직전에도 경로와 활동 시각을 재검사하며, 심볼릭 링크와 미확인 항목을 보호합니다.

조회 범위는 기본 DerivedData 폴더와 Xcode 전역 사용자 지정 위치입니다. 프로젝트별 상대 경로나 개별 `xcodebuild -derivedDataPath` 위치는 자동으로 포함하지 않습니다. 표시 용량은 할당 블록 기준이므로 APFS 공유 블록 등에 따라 실제 확보되는 공간과 다를 수 있습니다.

최근 조회와 정리 결과는 `~/Library/Application Support/MiniStats/`에 저장합니다.

### 스토리지 알림

홈 볼륨의 사용률이 **50% 이상**이면 경고 아이콘을 표시하고 알림을 한 번 보냅니다. 사용률이 50% 미만으로 내려갔다가 다시 기준을 넘으면 재알림합니다. 디스크 상태는 1분마다, 대시보드를 열 때도 확인합니다.

알림 권한을 허용하지 않아도 메뉴바 경고는 표시됩니다. 권한은 **설정 → 스토리지 알림 설정…**에서 변경할 수 있습니다. 배너 표시는 macOS 알림 설정과 집중 모드의 영향을 받습니다.

## 수치 해석과 지원 범위

- **CPU:** 대시보드는 전체 코어 기준 사용률입니다. 개별 프로세스는 코어 1개를 100%로 계산하므로 여러 코어를 쓰면 100%를 넘을 수 있습니다.
- **프로세스:** 접근 가능한 현재 사용자 소유 프로세스를 표시합니다. `kernel_task`, `WindowServer` 등 읽을 수 없는 프로세스는 제외되어 전체 CPU 사용률과 목록의 합이 다를 수 있습니다. 헬퍼는 부모 앱에 합치지 않고 각각 표시합니다.
- **메모리:** 시스템 사용량은 비제거성 내부 페이지·wired·압축 메모리의 합이며 파일 캐시는 제외합니다. 프로세스 메모리는 활성 상태 보기의 메모리 열과 같은 `phys_footprint` 기준입니다.
- **네트워크:** 활성 `en*` 물리 인터페이스의 합계입니다. VPN·브리지 중복 집계를 피하며 가상 인터페이스별 통계는 제공하지 않습니다.
- **스토리지:** 사용률은 `(전체 − 여유 공간) / 전체`입니다. Finder 기준 사용 가능 공간에는 정리 가능한 공간이 포함되므로 두 수치는 다를 수 있습니다.

Intel Mac용 빌드, GPU·센서·팬 제어, 코어별 사용률, 디스크 I/O 속도, 장기 기록 저장과 자동 업데이트는 제공하지 않습니다.

## 개발과 검증

| 명령 | 용도 |
| --- | --- |
| `make doctor` | 로컬 빌드 도구와 필수 파일 확인 |
| `make verify` | 릴리스 빌드와 전체 검사 |
| `make debug` | 디버거용 앱을 `build/debug/MiniStats.app`에 생성하고 검사 |
| `make test-python` | 임시 폴더에서 캐시 삭제·보존 회귀 검사 |

검사에는 실제 시스템 수치 읽기, CPU 계산과 PID 재사용 처리, 비동기 프로세스 조회, 스토리지 경계값, 선택한 캐시만 삭제하는 동작과 삭제 보호가 포함됩니다. **삭제 검사는 임시 폴더만 사용하며 실제 DerivedData를 삭제하지 않습니다.**

프로젝트 구조와 상세 검증 절차는 [개발 안내](docs/DEVELOPMENT.md)를 참고하세요. 버그 제보와 기능 제안은 [Issues](https://github.com/oozoofrog/MiniStats/issues)에 남길 수 있습니다.
