# SwiftUI 메뉴바 요약 패널 구현 계획

**목표:** 승인된 요약 패널 + 상세 창 분리를 SwiftUI로 구현하고 레트로 스타일을 유지한다.

**구조:** SwiftUI App / MenuBarExtra(.window) / 단일 Window를 사용한다. AppDelegate는 측정과 시스템 서비스만 담당한다. DashboardModel은 공유하되 요약 표시와 상세 프로세스 수집의 수명을 분리한다.

**범위:** macOS 26+, 외부 의존성 없음. 진단 인수와 기존 미커밋 변경 보존. UI 생성에 NSStatusItem, NSPopover, NSWindow/NSHostingView 래퍼를 사용하지 않는다. 기존 시스템 서비스 및 오프스크린 진단은 AppKit 사용 가능.

- [x] 요약 표시가 상세 탐색·프로세스 수집을 초기화하지 않는 회귀 검사를 추가하고 실패를 확인한다.
- [x] SwiftUI 앱 진입점, 메뉴바, 상세 Window, Commands 및 서비스 라우팅을 연결한다.
- [x] 픽셀 요약 행·상태 표시와 상세 이동을 구현한다. 미측정 값을 0으로 표시하지 않는다. 메뉴바 이미지는 template tint를 사용한다.
- [x] 오프스크린 요약 렌더링, 자체 검사 및 make verify를 실행한다. 기존 문서의 창 동작을 갱신한다.

**검토 초점:** 요약 닫기와 상세 창 수명 독립, 같은 상세 화면 재열기, 종료 중 정리 보호, 알림의 스토리지 이동, 진단 모드 서비스 미시작, 밝은/어두운 모드·큰 글씨.

**결정:** 사용자가 구현 진행을 승인했다. 기존 변경에 의존하므로 현재 작업 트리를 task/swiftui-menu-summary 브랜치로 보존한다. 설치·배포·커밋은 수행하지 않는다. 상세 창은 시스템 표준 리사이즈를 제공하며 초기 크기는 840×760으로 한다. 레트로 수치·채움 모양은 유지하되 메뉴바 상시 물결 타이머는 제거한다.


**검증 결과:** `make verify` 성공. 최종 전체 로그: `build/logs/verify-release-20261025-111703.RdQRQf`. 독립 리뷰의 마지막 페이지 초기화 지적을 수정했다. 실제 실행에서 App 수준의 장면 관찰이 동작하지 않아, 항상 존재하는 라벨 뷰에 명시적인 관찰과 openWindow를 배치하고 요청을 한 번만 소비하도록 수정했다. 상세 재열기·프로세스 수집 수명·요약 닫기·전경 활성화는 서비스 비활성 검증 사본에서 확인했다. 설치·배포·커밋은 하지 않았다. 세부 증거는 `docs/MENU_BAR_VALIDATION.md`에 기록한다.
