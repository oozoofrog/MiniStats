# MiniStats 대시보드 구현 검증 · 2026-09-12

> 2026-09-14 업데이트: 현재 프로젝트의 최소 지원 버전은 macOS 26으로 변경되었다. `arm64-apple-macos26.0`으로 빌드하며 macOS 13~25용 `NSVisualEffectView` fallback은 제거했다. 아래 2026-09-12 검증 기록은 변경 이전 시점의 기록이므로, 새 타깃에 대한 `make verify`는 macOS 26+ 빌드 환경에서 다시 실행해야 한다.

구현: AppKit 상태 메뉴를 SwiftUI 대시보드 팝오버로 교체했다. CPU/메모리 실측 및 최근 40회 추이, 상위 3개 미리보기와 PID를 포함한 상위 5개 상세, 네트워크, 스토리지 선택 정리, 설정을 연결했다. 당시 macOS 26+ `NSGlassEffectView`와 macOS 13~25 소재 대체, 투명도/동작 줄이기 대응을 포함했다.

## 빌드·회귀 검사

최종 명령 `make verify` 통과. 전체 로그: `../build/logs/verify-release-20260912-201917.yvpdYU`.

- 실제 시스템 CPU/메모리/네트워크 읽기, CPU 델타·wraparound, PID 재사용, 메모리 범위, 네트워크 카운터 재설정.
- 백그라운드 libproc 읽기, 첫 메모리 샘플, 유효하지 않은 CPU 측정 간격, 멀티코어 CPU 100% 초과, 동률 정렬.
- 비동기 모델 전달, 화면 닫기/다시 열기 이후 늦은 결과 배제.
- 저장 공간 50% 경계, 캐시 JSON 검증, 번들 리소스·서명·arm64 확인.
- 임시 디렉터리의 선택 항목만 삭제. 선택 대상 일부가 없거나 최근 사용되면 어떤 항목도 삭제하기 전에 중단.
- 기존 Xcode 실행 차단, 8시간 기준, 공용 캐시, 심볼릭 링크, 동시 파일 변경, 삭제 직전 재검사 회귀 검사 유지.

## 실제 GUI 관찰

macOS 27에서 최신 `build/MiniStats.app` 실행. Computer Use 연결을 다시 시도한 뒤 확인했다.

- 대시보드의 CPU/메모리 수치와 그래프 갱신, 각 상위 프로세스 3개 표시.
- CPU 상세 진입 → CPU/메모리 세그먼트 전환 → 상위 5개 이름·PID·사용량과 메모리 구성 표시.
- 대시보드 복귀 → 스토리지 열기, 한 항목 선택: 1개·1.12GB.
- 정리 확인 창에 선택한 한 경로와 용량만 표시. 취소했다. 실제 사용자 캐시는 삭제하지 않았다.
- 모두 선택: 14개·3.59GB. 선택 해제: 0개·0B이며 정리 버튼 비활성.
- 설정 화면에서 로그인 실행 상태와 알림 설정 경로 확인. `--notification-status`: authorized true, alerts enabled true.
- 최종 접근성 보정 후 앱을 다시 실행해 스토리지 카드가 button으로 노출되는 것 확인.

최종 실행은 빌드 폴더의 앱이다. `/Applications/MiniStats.app`를 덮어쓰거나 새 설치를 수행하지 않았다.

## 검사 한계

- GUI에서 실제 삭제는 수행하지 않았다. 삭제 보호 검사는 임시 디렉터리만 사용했다.
- 로그인 후 재실행, 실제 알림 배너 전달, 실제 시스템 외관 전환·투명도 줄이기 조작은 별도 미검증이다.
- 밝은/어두운 모드 PNG는 SwiftUI 콘텐츠 렌더링이며 유리 효과 합성 검증과 구별한다. ImageRenderer는 네이티브 세그먼트 등 일부 AppKit 컨트롤을 렌더링하지 못하므로 상세 화면 PNG의 자리표시는 앱 오류의 근거로 사용하지 않는다. 네이티브 세그먼트는 실제 GUI에서 확인했다.
- 화면 제어 연결 전 숨겨진 팝오버를 캡처한 이미지는 실제 열린 화면의 근거가 아니어서 제거했다.
- SourceKit-LSP는 직접 swiftc로 묶는 다른 파일의 심볼을 찾지 못했다. 컴파일 결과는 실제 세 파일 빌드로 검증했다.
